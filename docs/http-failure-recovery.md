# HTTP failure contracts / HTTP 失败契约

The operator event list, metrics, retry endpoint and signed webhook now return
`503 {"error":"storage_unavailable"}` if storage raises. Database URLs, credentials,
payloads and provider exception text are not included in that response. A failed
write may have committed before the connection failed: resend the same webhook
source, body and `Idempotency-Key`, not a new key. Existing durable uniqueness
handles an already accepted write. Do not treat a 503 as proof of rollback.

Non-ASCII invalid Authorization/signature headers return 401 instead of an
uncaught `compare_digest` error. A correctly signed body with invalid text encoding
returns 400 and is not ingested. The signature remains exactly 64 lowercase hex
characters as generated by the bundled WordPress connector.

Operator endpoints require authorization before querying storage. These changes
do not add unauthenticated access, reset records, migrate a schema, automatically
replay client requests, or assert real WordPress-to-CRM acceptance.

Run `python -m unittest discover -s tests -p test_http_failures.py -v`.
The regression uses a real local HTTP server and injected storage failures; it is
not a real database outage drill. The existing PostgreSQL/container CI remains a
separate gate. Rollback is code-only with no data migration, but removes these
structured failure guarantees. Preserve keys and queue records during rollback.

## 中文

事件列表、监控、操作员重试和已签名 Webhook 的存储异常统一返回 503，响应中
不包含数据库地址、密钥、客户数据或底层异常。503 不保证事务回滚：写入可能在
连接失败前已提交。客户端应使用相同来源、正文和幂等键重试，避免另造键导致重复。

非 ASCII 的错误鉴权/签名头返回 401，不再因比较函数报错而断开连接；签名正确
但正文编码错误返回 400，不入库。签名仍要求与随附 WordPress 插件一致的 64 位
小写十六进制。操作员接口仍先鉴权再访问存储。

测试通过真实本地 HTTP 服务注入存储异常，不冒充真实数据库故障演练或外部 CRM
验收。现有 PostgreSQL 容器 CI 仍单独运行。回滚无需迁移，但会移除结构化失败
响应保证；回滚时保留队列数据和幂等键，不自动重放数据。
